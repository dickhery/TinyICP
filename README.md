# TinyICP

Tiny ICP is a prepaid URL shortener built on the Internet Computer. Inspired by the Liminal URL Shortener template on ICP.Ninja by Gekctek (Ethan Celletti) and the Liminal HTTP framework by edjCase (MIT license). Expanded on by Richard Hery.

A retro terminal-styled URL shortener showcasing HTTP-native features on the Internet Computer.

## Features

- Retro terminal UI
- Prepaid URL shortening with click tracking
- Custom short codes
- Destination Open Graph / Twitter card previews on `https://tinyicp.com/s/{shortCode}`
- Internet Identity sign-in
- HTTP-native redirects from the backend canister

## Link previews

Social previews for TinyICP short links are generated by the **backend Motoko canister**, not the static frontend.

`https://tinyicp.com/s/{shortCode}` only shows the destination title/image when `/s/*` is routed to the backend. The Cloudflare Worker in [`cloudflare/worker.js`](./cloudflare/worker.js) does that:

1. `/s/*` goes to the backend canister (raw gateway) so crawlers receive Open Graph HTML
2. every other path goes to the frontend canister
3. `x-tinyicp-forwarded-host` and `x-tinyicp-forwarded-proto` keep `og:url` on `tinyicp.com`

Known social crawlers (Facebook, Twitter/X, Slack, Discord, WhatsApp, iMessage, and similar) are served that preview HTML as a **query**. That avoids a consensus round-trip, does not burn a prepaid click, and keeps cycle use low. Human visits still go through the update path that records the click.

The dashboard copies branded `https://tinyicp.com/s/{shortCode}` links by default.

## Getting started

Install [icp-cli](https://cli.internetcomputer.org), `ic-wasm`, `ic-mops`, and Node.js 22+.

```bash
npm install -g @icp-sdk/icp-cli @icp-sdk/ic-wasm ic-mops
npm install
```

Local network:

```bash
icp network start -d
icp deploy
```

The local frontend is at `http://frontend.local.localhost:8000`. Vite frontend-only development:

```bash
icp network start -d
icp deploy backend
npm run start
```

Then open `http://localhost:3000`.

Mainnet:

```bash
icp deploy -e ic
```

The frontend canister uses the certified-assets recipe. The first time this project is switched from the legacy dfx asset canister, frontend install must use `--mode reinstall` (it wipes and re-uploads static files; backend state is not affected):

```bash
icp deploy backend -e ic
icp deploy frontend -e ic --mode reinstall
```

Later frontend updates can use a normal `icp deploy frontend -e ic`.

## Backend HTTP

Short-link routes served by the Motoko canister:

- `GET /s/{shortCode}` — preview HTML + redirect for browsers
- `HEAD /s/{shortCode}` — existence check without a body
- `GET /s/{shortCode}/stats` — click statistics

Authenticated URL create/list/delete/top-up goes through the canister Candid API from the frontend, not the old `/shorten` HTTP form.

Local examples:

```bash
curl -i http://backend.local.localhost:8000/s/abc123
curl http://backend.local.localhost:8000/s/abc123/stats
```

Mainnet (also works through the custom domain):

```bash
curl -i https://tinyicp.com/s/abc123
curl -i https://swan4-qqaaa-aaaab-aga5a-cai.raw.icp0.io/s/abc123
```

## Configuration

- `VITE_PUBLIC_SHORTLINK_ORIGIN` — branded short-link origin (default `https://tinyicp.com`)
- `VITE_SHARE_SHORTLINK_ORIGIN` — origin used when copying links (defaults to the public origin)
- `VITE_INTERNET_IDENTITY_URL` — override Internet Identity authorize URL (default `https://id.ai/authorize`)

Frontend canister IDs and the replica root key come from the `ic_env` cookie set by the static-site canister (or by the Vite dev server). There is no dfx `.env` / `CANISTER_ID_*` injection.

## Cycles

Preview metadata fetches attach only the cycles `Prim.costHttpRequest` reports for a 100 KB max response, instead of a fixed 230B attach. Crawler preview GETs are queries, so they do not consume update-call cycles or prepaid clicks.
